# Meson Backend for moz.build

This document describes the Meson backend for Mozilla's build system, which allows generating `meson.build` files from `moz.build` definitions.

## Overview

The Meson backend (`MesonBackend`) is a build backend that converts Mozilla's `moz.build` files into Meson build system files (`meson.build`). This enables using Meson as an alternative build system for Mozilla projects.

## Usage

To use the Meson backend, specify it when configuring the build:

```bash
./mach build --backend=Meson
```

Or configure it in your `mozconfig`:

```
ac_add_options --enable-backend=Meson
```

## Supported Features

The Meson backend supports a comprehensive set of moz.build constructs:

### Build Targets
- **Programs**: `PROGRAM` variable generates `executable()` targets
- **Simple Programs**: `SIMPLE_PROGRAMS` generates multiple `executable()` targets
- **Host Programs**: `HOST_PROGRAM` and `HOST_SIMPLE_PROGRAMS` generate native `executable()` targets  
- **Rust Programs**: `RUST_PROGRAMS` and `HOST_RUST_PROGRAMS` (with notes about Rust support)
- **Static Libraries**: `STATIC_LIBRARY_NAME` generates `static_library()` targets
- **Shared Libraries**: `SHARED_LIBRARY_NAME` generates `shared_library()` targets
- **Rust Libraries**: `RustLibrary` and `HostRustLibrary` support

### Source Files
- **C/C++ Sources**: `SOURCES` variable
- **Host Sources**: `HOST_SOURCES` variable
- **Unified Sources**: Handled through `SOURCES`

### Compilation Settings
- **Defines**: `DEFINES` and `HOST_DEFINES` generate `-D` flags
- **Local Includes**: `LOCAL_INCLUDES` generates `include_directories()`
- **Computed Flags**: Compiler flags from `CFLAGS`, `CXXFLAGS`, etc.
- **Per-Source Flags**: Source-specific compilation flags

### Build Structure
- **Directory Traversal**: `DIRS` generates `subdir()` calls
- **Generated Files**: `GENERATED_FILES` (documented as comments)
- **Exports**: `EXPORTS` (tracked for reference)

### Other Features
- **Variable Passthrough**: `VARIABLES` for passing build variables
- **Host/Target Distinction**: Proper handling of cross-compilation scenarios

## Generated Files

The backend generates:

1. **Top-level `meson.build`**: Contains project definition and subdirectory references
2. **Per-directory `meson.build` files**: Contain build targets for each directory with sources/programs/libraries

## Example

Given a `moz.build` file:

```python
SOURCES += ['foo.cpp', 'bar.cpp']
PROGRAM = 'myapp'
```

The backend generates a `meson.build`:

```meson
# Generated by mozbuild's Meson backend

# Program: myapp
sources = [
  'foo.cpp',
  'bar.cpp',
]

executable('myapp', sources)
```

## Limitations

The Meson backend is a partial backend and has some limitations:

- Not all moz.build features are supported yet
- Complex build configurations may not translate perfectly
- Some Mozilla-specific build logic may need manual translation

## Testing

Tests for the Meson backend are located in:
- `python/mozbuild/mozbuild/test/backend/test_meson.py`

Run tests with:

```bash
./mach python-test python/mozbuild/mozbuild/test/backend/test_meson.py
```

## Implementation

The backend implementation is in:
- `python/mozbuild/mozbuild/backend/meson.py`

The backend extends `PartialBackend` and implements:
- `consume_object()`: Processes individual build objects
- `consume_finished()`: Generates final meson.build files
